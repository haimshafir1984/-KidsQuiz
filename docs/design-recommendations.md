## P1 — לפני הצגה ללקוח

### 1. טקסט פנימי שדלף לממשק
ב-[WelcomePage.jsx:49](../src/pages/WelcomePage.jsx) מופיע בעמוד הפתיחה הטקסט:
> "זאת נקודת פתיחה טובה למצגת מכירתית שנלטש יחד בהמשך."

זה טקסט עבודה פנימי שמופיע ללקוח הסופי. להחליף בניסוח שיווקי או להסיר את הקופסה כולה.

### 2. סימון שדות חובה בטופס ההרשמה
הודעת השגיאה אומרת "יש למלא את כל שדות החובה", אבל אף שדה לא מסומן ויזואלית כחובה. טלפון ותאריך לידה אופציונליים — והמשתמש לא יכול לדעת זאת.
**המלצה:** כוכבית (או תגית "חובה") ליד שדות חובה, ותגית "אופציונלי" ליד טלפון ותאריך לידה. ולידציה פר-שדה עם הודעה מתחת לשדה, במקום הודעה כללית אחת.

### 3. מצבי פוקוס למקלדת
לשדות קלט יש `focus:ring-2` יפה, אבל לכפתורים (`btn-primary`, `btn-secondary`, `quiz-option`, טאבים) **אין שום סגנון focus-visible** — ניווט מקלדת בלתי נראה.
**המלצה:** להוסיף גלובלית ב-`index.css`:
```css
@layer base {
  :focus-visible {
    @apply outline-none ring-2 ring-blue-500 ring-offset-2;
  }
}
```

### 4. חיווי זמן במבחן
תצוגת "זמן נותר" סטטית לכל אורך המבחן. בדקה האחרונה אין שום שינוי ויזואלי.
**המלצה:** מתחת לדקה — צבע אדום + pulse עדין; מתחת ל-10 שניות — גם ספירה בולטת. (כלול גם בהוראת הביצוע של מסמך ה-QA.)

### 5. אייקון placeholder בעמוד הפתיחה
הכרטיס "תמונה ברורה להורים" משתמש באייקון `Dot` — נראה כמו שיבוש. להחליף ב-`LineChart` או `Users`.

## P2 — עקביות שפת העיצוב (Design Tokens)

### 6. ריבוי רדיוסי פינות שרירותיים
בקוד מפוזרים: `rounded-lg`, `xl`, `2xl`, `3xl`, `rounded-[20px]`, `[22px]`, `[24px]`, `[26px]`, `[28px]`, `[30px]`. אין היגיון נראה מתי משתמשים במה.
**המלצה:** להגדיר ב-`tailwind.config.js` סולם של 3–4 ערכים סמנטיים ולהחליף את כל הערכים השרירותיים:
```js
borderRadius: {
  card: '20px',      // כרטיסים רגילים
  'card-lg': '28px', // כרטיסי hero/מודאלים
  pill: '9999px',
}
```

### 7. צללים שרירותיים
לפחות 6 הגדרות `shadow-[0_..._rgba(...)]` שונות בקבצים שונים (AuthPage, index.css, demo-*). להגדיר 2–3 טוקנים (`shadow-card`, `shadow-float`, `shadow-modal`) ב-tailwind.config ולהשתמש רק בהם.

### 8. פלטת צבעים רחבה מדי
כחול הוא צבע המותג, אבל בפועל משמשים גם: violet, sky, indigo, cyan, rose, emerald, amber, red — לעתים לאותו תפקיד (למשל תגיות מידע פעם ב-sky, פעם ב-violet, פעם ב-blue).
**המלצה:** לקבע תפקידים סמנטיים ולצמצם:
| תפקיד | צבע |
|-------|-----|
| מותג / פעולה ראשית | blue-600 |
| הדגשה משנית (גרדיאנטים, badges) | violet-600 בלבד |
| הצלחה | emerald |
| אזהרה / מבחן / טיימר | amber |
| שגיאה / מחיקה | red |
| ניטרלי | slate |

את sky/indigo/cyan/rose להשאיר רק ל-`LETTER_BADGES` בחידון (שם הצבעוניות מכוונת).

### 9. `btn-secondary` ו-`btn-muted` זהים כמעט לחלוטין
שניהם: רקע לבן, גבול slate-200, טקסט slate-700, אותו hover. ההבדל היחיד — `shadow-sm`. למזג לאחד, או לתת ל-muted מראה "שקוף" אמיתי (ללא גבול, טקסט בלבד).

### 10. טיפוגרפיה — bold מול extrabold
מסמך העיצוב הקודם קבע `font-bold` לכותרות ו-`font-extrabold` רק ל-hero ולחידון, אבל בקוד הנוכחי extrabold חזר כמעט לכל כותרת (Summary, Quiz, Auth, Admin).
**המלצה:** להחליט ולאכוף: `font-bold` ככלל; `font-extrabold` רק ל-h1 של hero ולנוסח השאלה בחידון. זה מרכך את המראה ומחזק את ההיררכיה.

### 11. אנימציות מותאמות חסרות
`tailwind.config.js` כמעט ריק — אין את `bounceIn` / `shake` / `pop` שמוזכרות ב-CLAUDE.md. משוב נכון/שגוי בחידון מופיע סטטית.
**המלצה:** להוסיף שלוש אנימציות עדינות:
- תשובה נכונה: `pop` קצר (scale 0.97→1) על קופסת המשוב.
- תשובה שגויה: `shake` עדין (לא מוגזם — קהל היעד רגיש לתחושת כישלון).
- מעבר שאלה: fade+slide קצר.
ולהוסיף `@media (prefers-reduced-motion: reduce)` שמכבה את כולן.

## P3 — שיפורי מסכים נקודתיים

### 12. חידון (QuizPage)
- **חגיגת סיום:** ב-100% להוסיף רגע קטן של קונפטי/כוכבים במסך הסיכום — מחוות ההצלחה היום היא אימוג'י סטטי (💎). עדין, חד-פעמי, לא ילדותי.
- **מעבר בין שאלות:** כרטיס השאלה מתחלף בלי טרנזיציה — קפיצה חדה. fade קצר של 150ms מספיק.
- **פס ההתקדמות** כבר עם גרדיאנט יפה — להוסיף `transition-all duration-500` כדי שהמילוי יזחל חלק (יש duration-200, אפשר להאריך).
- שאלה עם יותר מ-6 אפשרויות תציג badge ריק (מגבלת `LETTER_BADGES`) — לגדר או להגביל בטופס הניהול.

### 13. מבחן כללי
- לפני "סיום מבחן" אין חיווי כמה שאלות נשארו ריקות — להוסיף מונה "נענו X מתוך Y" ליד הכפתור, ודיאלוג אישור אם יש ריקות.
- ברשימת 5 השאלות בעמוד אין חיווי ויזואלי מהיר אילו נענו — להוסיף סימן ✓ קטן בכותרת שאלה שנענתה.

### 14. סיכום (SummaryPage)
- במבחן הכללי כדאי להוסיף **פילוח לפי נושא** (כמה נכונות בכל תת-נושא) — המבחן מערבב נושאים וזה המידע הכי שימושי להורה.
- כפתור "התחלה מחדש" ראשי (כחול) ו"חזרה למסלול" משני — נכון. אבל אחרי מבחן אולי עדיף ש"חזרה למסלול" יהיה הראשי; התחלה מחדש מיידית של מבחן שלם היא פעולה נדירה.

### 15. כותרת (Header)
- כפתור "ניהול" מוצג לכל משתמש — בשלב הדמו זה מכוון, אבל כשמציגים ללקוח כתלמיד זה עלול לבלבל. לשקול toggle תצוגה בזמן דמו.
- במובייל השורה נשברת לשלוש שורות (לוגו + ניווט + משתמש) — לשקול תפריט המבורגר מתחת ל-640px.
- לכפתורי הניווט יש מצב active לפי `location.pathname` מדויק בלבד — "בחירת כיתה" לא מסומן כפעיל כשנמצאים ב-`/subject` או `/track`. לסמן לפי תחילת המסלול.

### 16. ניהול (AdminPage)
- שורת הסינון sticky על `top-4` ו-BulkActionsBar על `top-24` — כששניהם פעילים הם חופפים לכותרת בגלילה. לבדוק ולכייל.
- בטבלת השאלות, טקסט שאלה ארוך נחתך? לוודא `line-clamp-2` עם tooltip לנוסח המלא.
- כפתורי האייקונים (הזזה/מחיקה) — להוסיף `title` ו-`aria-label`.

### 17. נגישות עיצובית (משלים את מסמך ה-QA)
- ניגודיות: `text-slate-400` על רקעים בהירים (placeholders, טקסט עזר) מתחת ל-AA. להעלות ל-slate-500 לפחות בטקסט משמעותי.
- מודאלים (Drawer, ConfirmDialog, פאנל משתמש ב-AdminUsers): `role="dialog"`, `aria-modal`, סגירה ב-Escape ובלחיצה על הרקע, focus-trap.
- גדלי מגע: כפתורי האייקונים בטבלאות קטנים מ-44px — להגדיל את אזור הלחיצה.
