# מעבר לפרודקשן: דומיין ו-Dokploy

מסמך זה מפרט מה צריך להכין בצד התשתית (דומיין, Cloudflare, Dokploy, בסיס נתונים, מייל, גיבויים וניטור) כדי שאפשר יהיה להעלות את המערכת לפרודקשן ולשלוח ללקוחות קצה.
המסמך כתוב כך שאפשר להעביר אותו כמו שהוא לצ'אט שעוזר בהקמה. בכל סעיף מצוין מה צריך לעשות, ומה אני (מצד הקוד) צריך לקבל ממך כשזה מוכן.

מצב קיים: אתר סטטי (React) ב-Dokploy על שרת Contabo, מאחורי Cloudflare, בכתובת `kidsquiz.flowsbiz.com`. אין בסיס נתונים ואין שרת API.

---

## חלק א: דומיין

### 1. בחירה ורכישה
- דומיין ייעודי לפרויקט, **לא** תת-דומיין של `flowsbiz.com`. הסיבה: `flowsbiz.com` סווג בעבר כ-Phishing בסינון (OpenText/Webroot), ותת-דומיינים שלו יורשים את הסיווג. דומיין חדש ונקי מתחיל בלי היסטוריה.
- אפשרויות:
  - `.com`: אפשר לרכוש ב-Cloudflare Registrar במחיר עלות, ניהול DNS באותו מקום. הכי מהיר.
  - `.co.il`: מעורר אמון בציבור הישראלי, אבל נרכש דרך רשם ישראלי מוסמך (לא Cloudflare). נדרש בעל דומיין ישראלי (עוסק או חברה). ה-DNS אפשר להעביר ל-Cloudflare על ידי שינוי ה-Nameservers.
- הרישום על שם **בעל העסק** (לא על שם פרטי של מי שמקים), עם אימות דו-שלבי, נעילת דומיין (Domain Lock), הגנת WHOIS וחידוש אוטומטי.
- לפני רכישה: לוודא שהשם פנוי, ושאין בו מילים שמסינון עלול לסמן (שמות עם "login", "bank", "secure" וכד').

### 2. Cloudflare (DNS ו-SSL)
- להוסיף את הדומיין ל-Cloudflare ולהעביר אליו את ה-Nameservers.
- רשומות DNS (כתובת השרת ב-Contabo = `SERVER_IP`):
  | סוג | שם | ערך | Proxy |
  |---|---|---|---|
  | A | `@` (השורש) | `SERVER_IP` | מופעל (ענן כתום) |
  | CNAME | `www` | `@` | מופעל |
  | A | `staging` | `SERVER_IP` | מופעל (סביבת בדיקה, ר' חלק ב) |
- הפניה: `www.<דומיין>` מפנה ל-`<דומיין>` (Redirect Rule, קוד 301).
- SSL/TLS:
  - מצב **Full (strict)**.
  - Always Use HTTPS: מופעל.
  - Minimum TLS: 1.2.
  - HSTS: להפעיל רק אחרי שהכול עובד תקין, כי קשה לבטל.
  - Certificate Authority: **Google Trust Services** (שרשרת ותיקה שנתמכת בכל מכשיר), במקום Let's Encrypt החדש.
- הגנות: Bot Fight Mode פעיל, אבל לוודא שלא חוסם את `/api`. כלל Rate Limiting על `/api/auth/*` (כניסה והרשמה).
- Caching: קבצי `/assets/*` עם Cache Everything ו-Edge TTL ארוך (הקבצים מכילים hash בשם), ו-`index.html` בלי cache.
- לכבות Rocket Loader ו-Auto Minify (עלולים לשבור את האפליקציה).

### 3. דומיין הדמו הישן
- להשאיר את `kidsquiz.flowsbiz.com` פעיל זמנית, ואחר כך להגדיר הפניית 301 לדומיין החדש, כדי שקישורים שנשלחו ללקוחה ימשיכו לעבוד.
- להסיר אותו מכל קישור בקוד (הורדת גרסת מחשב, מצגות). אני אעדכן בקוד, אחרי שיש שם.

### 4. מייל (חובה להרשמה ושחזור סיסמה)
- **שליחה** (אימות מייל, שחזור סיסמה): שירות שליחה ייעודי, למשל Resend, Postmark, Brevo או Amazon SES. לא שולחים מה-SMTP של השרת עצמו.
- **קבלה** (כתובות כמו `support@<דומיין>`): Google Workspace, Zoho Mail או Cloudflare Email Routing (העברה לתיבה קיימת).
- רשומות DNS שיש להוסיף (הערכים המדויקים נותן ספק המייל):
  - SPF: רשומת TXT על `@`.
  - DKIM: רשומת TXT או CNAME לפי הספק.
  - DMARC: TXT על `_dmarc`, להתחיל ב-`p=none` ולעבור ל-`quarantine` אחרי שבוע של דוחות תקינים.
  - MX: אם מקבלים מייל בדומיין.
- כתובת שולח מומלצת: `no-reply@<דומיין>`, וכתובת תמיכה: `support@<דומיין>`.

### 5. מוניטין וסינון (לפני שליחה ללקוחות)
הקהל מסונן במקרים רבים. לפני ההשקה:
1. לבדוק את הדומיין ב-[OpenText URL lookup](https://support.threatintel.opentext.com/tools/url-ip-lookup.php) (זה מה שהזין את החסימה הקודמת), ולבקש סיווג **Education**.
2. לבדוק ב-Google Safe Browsing ו-VirusTotal.
3. לפנות לספקי הסינון הנפוצים בציבור היעד (למשל נטפרי, NetFree, רימון, ובזק Bcyber) ולבקש הכללה.
4. אחרי הרכישה לבדוק שוב כל כמה ימים לפני ההשקה.

### 6. מה אני צריך ממך מהחלק הזה
- שם הדומיין הסופי.
- אישור שה-DNS ב-Cloudflare הוגדר ושהאתר נפתח תקין ב-https.
- ספק המייל שנבחר (לשליחה), ומה כתובת השולח.

## חלק ב: Dokploy ושרת

### 1. מבנה סופי של השירותים
```
Cloudflare  ->  Traefik (Dokploy)  ->  web   (nginx עם האתר הסטטי)   [קיים]
                                   ->  api   (שרת Node)               [חדש]
                                   ->  db    (PostgreSQL)             [חדש, פנימי בלבד]
```
- דומיין אחד לשניהם: האתר בנתיב `/`, ושרת ה-API בנתיב `/api`. כך אין בעיות CORS ועוגיות ההתחברות פועלות בצד אחד.

### 2. בסיס נתונים (PostgreSQL)
- ב-Dokploy: Project חדש (או הקיים), ואז **Database ← PostgreSQL** (גרסה 16 ומעלה).
- הגדרות:
  - שם בסיס נתונים: `kidsquiz`. משתמש ייעודי: `kidsquiz_app` עם סיסמה ארוכה אקראית (32 תווים ומעלה).
  - **בלי חשיפה החוצה:** לא לפתוח פורט ציבורי. ה-API ניגש דרך הרשת הפנימית של Dokploy (שם השירות הפנימי כ-host).
  - Volume קבוע (Persistent), כדי שהנתונים לא ייעלמו בעדכון.
- גיבויים (חובה):
  - להגדיר Backup Destination (S3 או תואם): Cloudflare R2, Backblaze B2 או Contabo Object Storage.
  - גיבוי **יומי**, שמירה של 14 עד 30 יום.
  - לבדוק פעם אחת **שחזור** מגיבוי לבסיס נתונים נפרד. גיבוי שלא נבדק הוא לא גיבוי.
- רשימת הסודות שמחזיקים במנהל סיסמאות (לא בקוד ולא בצ'אט): סיסמת בסיס הנתונים, סיסמאות המנהלים, מפתחות המייל (כשיוגדר ספק).

### 3. שירות ה-API (חדש)
- Application חדש ב-Dokploy, מהמאגר ב-GitHub, עם Dockerfile בתיקיית `server/` (אני אכין).
- משתני הסביבה, הנתיבים והפקודות הראשונות: ראו **docs/DOKPLOY_API_SETUP.md** (מדריך מדויק, מעודכן לקוד בפועל).
- Health check: `/api/health`. Restart policy: `always`. הגבלת משאבים: למשל 512MB זיכרון.

### 4. שירות האתר (קיים)
- להשאיר את ה-Dockerfile הקיים. אני אעדכן את ההגדרות כך ש-`/api` לא יטופל כקובץ סטטי.
- Build Arg: `VITE_OFFLINE_DOWNLOAD_URL` ממשיך להיות מוגדר.
- Auto Deploy מ-GitHub (Webhook) על הענף `main`.

### 5. סביבת בדיקה (Staging)
- ב-Dokploy: סביבה נפרדת (Project או Environment) עם בסיס נתונים **נפרד** ושירות API נפרד.
- כתובת `staging.<דומיין>`, מוגנת בסיסמה (Cloudflare Access או Basic Auth), כדי שלא תיכנס לאינדקס ולא תיחשף.
- Auto Deploy מענף `staging`. כל שינוי נבדק שם לפני מיזוג ל-`main`.
- לעולם לא להשתמש בנתוני לקוחות אמיתיים בסביבת הבדיקה.

### 6. אבטחת השרת (Contabo)
- עדכוני מערכת אוטומטיים (`unattended-upgrades`).
- חומת אש (UFW או חומת האש של Contabo): פתוחים רק 80, 443 ו-22. את פורט הניהול של Dokploy (3000) להגביל לכתובת IP שלך, או לגשת אליו רק דרך דומיין מוגן.
- SSH עם מפתחות בלבד (בלי סיסמה), וחסימת root מרחוק. `fail2ban` מותקן.
- Snapshot של השרת לפני שינויים גדולים (ב-Contabo).
- לוודא שיש מספיק משאבים: מומלץ לפחות 4GB זיכרון ו-40GB פנויים. לעקוב אחרי נפח הדיסק.

### 7. ניטור והתראות
- **זמינות:** Uptime Kuma (זמין כ-Template ב-Dokploy). בודק את `https://<דומיין>` ואת `/api/health` כל דקה, ושולח התראה לוואטסאפ, טלגרם או מייל.
- **שגיאות:** Sentry (חבילה חינמית) או GlitchTip (מותקן על השרת). אני אוסיף את החיבור בקוד אחרי שנבחר.
- **לוגים:** לוודא שב-Dokploy רואים לוגים של ה-API ושל בסיס הנתונים, ושהם מתחלפים (לא ממלאים דיסק).

### 8. GitHub
- המאגר: להשאיר פרטי. להפעיל Branch Protection על `main`.
- סודות לבניית גרסת המחשב (חתימת קוד) יוגדרו כ-Secrets ב-GitHub Actions, לא בקוד.

### 9. מה אני צריך ממך מהחלק הזה
- אישור ש-PostgreSQL הוקם ב-Dokploy, ושם השירות הפנימי שלו (בלי הסיסמה).
- אישור שהגיבויים הוגדרו ונבדק שחזור.
- אישור שנוצרה סביבת בדיקה ושם הדומיין שלה.
- את הסודות מגדירים אתה ישירות ב-Dokploy. **אל תשלח אותם לצ'אט או לי**; מספיק שתאשר שהוגדרו.
