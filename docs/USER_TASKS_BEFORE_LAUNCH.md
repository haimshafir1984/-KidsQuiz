# משימות לביצוע שלך (תשתיות וממשקי ניהול) לפני השקה

מסמך זה נועד לעבודה עם הצ'אט. את צד הקוד אני מבצע במקביל (ר' סעיף 11). כל משימה כוללת: למה, מה לעשות, ואיך מוודאים שהצליח.

## כללי עבודה (להדביק לצ'אט בתחילת השיחה)
- על אותו שרת ואותו דומיין (`flowsbiz.com`) רצות **מערכות נוספות**. אסור לבצע שינוי כללי ברמת האזור/השרת. כל כלל ב-Cloudflare חייב להיות מוגבל ל-`kidsquiz.flowsbiz.com` בלבד, וכל שינוי בשרת חייב להיבדק מול המערכות האחרות.
- **לא להדביק בצ'אט** סיסמאות, מפתחות API, ערכי משתני סביבה או טוקנים. מדביקים רק שמות וצילומי מסך שבהם הערכים מוסתרים.
- לפני כל שינוי שמסכן גישה (חומת אש, SSH): לשמור חיבור פתוח אחד נוסף, ולדעת איך חוזרים אחורה (Console של Contabo).
- משימה אחת בכל פעם. אחרי כל משימה לבדוק שהאתר, ה-API והמערכות האחרות עדיין עובדים.

## מצב נוכחי (למי שמתחיל מאפס)
- אתר + API: `https://kidsquiz.flowsbiz.com` ו-`/api`, שירותים `kidsquiz-web` ו-`kidsquiz-api` ב-Dokploy על VPS של Contabo.
- בסיס נתונים: PostgreSQL 16 פנימי (`kidsquiz-db`), גיבוי יומי ל-Cloudflare R2.
- Cloudflare חינמי, SSL = Full. Dokploy נגיש כרגע ב-HTTP על IP:3000.

## סטטוס ביצוע (מעודכן)

## עדיפות 1 – חובה לפני השקה

### 1. לסגור את ממשק Dokploy מהאינטרנט
**למה:** הסיסמה עוברת בגלוי (HTTP), ומי שנכנס שולט בכל מה שרץ על השרת, כולל המערכות האחרות.
**מה לעשות (אחת מהאפשרויות):**
- (מומלץ) לגשת רק דרך Tailscale/WireGuard או מנהרת SSH (`ssh -L 3000:localhost:3000 user@server`), ולחסום את פורט 3000 לעולם.
- או לחשוף את Dokploy בדומיין ייעודי עם HTTPS (ב-Dokploy: Settings → Server → Domain) ואז לחסום את הפורט הישיר.
**אימות:** מרשת אחרת (למשל הטלפון על נתונים סלולריים) `http://<IP>:3000` לא נפתח; Dokploy נפתח בדרך שבחרת.

### 2. חומת אש ופורטים (כולל Docker)
**למה:** Docker מפרסם פורטים ועוקף את UFW. פורט שנראה סגור יכול להיות פתוח.
**מה לעשות:**
- לרשום מה אמור להיות פתוח: 22 (SSH, עדיף מוגבל ל-IP שלך), 80, 443. כל השאר סגור.
- לבדוק מבחוץ מה פתוח באמת (`nmap -Pn <IP>` ממחשב/שרת אחר), ולהשוות לרשימה.
- לוודא שפורטים של בסיס נתונים (5432) ושל ה-API (3000) לא מפורסמים לעולם. הגישה אליהם רק דרך הרשת הפנימית של Dokploy.
- אם משתמשים ב-UFW: לטפל גם בשרשרת `DOCKER-USER` (או להשתמש בחומת האש של Contabo ברמת הרשת).
**אימות:** `nmap` מראה רק את הפורטים המותרים. כל המערכות האחרות על השרת עדיין עובדות.

### 3. הקשחת SSH ועדכונים
**מה לעשות:**
- כניסה רק עם מפתח SSH (`PasswordAuthentication no`), בלי כניסת root ישירה (`PermitRootLogin no`).
- להתקין ולהפעיל `fail2ban` (jail ל-sshd).
- להפעיל עדכוני אבטחה אוטומטיים (`unattended-upgrades` ב-Ubuntu/Debian).
- **לפני** שמנתקים חיבור: לפתוח חיבור שני ולוודא שהמפתח עובד.
**אימות:** ניסיון כניסה עם סיסמה נדחה; `fail2ban-client status sshd` פעיל; `unattended-upgrades --dry-run` עובד.

### 4. כללים ב-Cloudflare (רק לדומיין שלנו)
כל כלל בעורך חייב לכלול תנאי `Hostname equals kidsquiz.flowsbiz.com`.
1. **Cache Rule:** נתיב המתחיל ב-`/api/` → **Bypass cache**. (ככל הנראה זה היה מקור בעיית ההתחברות הראשונה.)
2. **Redirect Rule:** HTTP → HTTPS רק לדומיין שלנו (במקום Always HTTPS לכל האזור). בלי זה, כניסה ב-`http://` לא תתחבר כי העוגייה מוגדרת Secure.
3. **Rate Limiting Rule** (בחבילה החינמית כלל אחד): נתיבים `/api/auth/` → למשל 20 בקשות ל-10 שניות ל-IP, פעולה Block/Managed Challenge לדקה.
4. (אופציונלי) **Configuration Rule:** SSL = Full (strict) רק לדומיין שלנו. בדוק קודם שתעודת Let's Encrypt בשרת תקפה לדומיין. אם משהו נשבר, מבטלים את הכלל.
**אימות:** `curl -I https://kidsquiz.flowsbiz.com/api/health` מחזיר `cf-cache-status: DYNAMIC` או BYPASS; `curl -I http://kidsquiz.flowsbiz.com` מפנה ל-https; מערכות אחרות על `flowsbiz.com` לא הושפעו.

### 5. Cloudflare Turnstile להרשמה (חינמי)
**למה:** ההרשמה פתוחה ובלי אימות מייל, ולכן בוטים יכולים ליצור אלפי חשבונות עם ניסיון חינם.
**מה לעשות:**
1. ב-Cloudflare: Turnstile → Add widget. Domain: `kidsquiz.flowsbiz.com`. Mode: Managed.
2. מקבלים שני ערכים: **Site Key** (ציבורי) ו-**Secret Key** (סודי).
3. אחרי שאני מעדכן את הקוד (ר' סעיף 11), ב-Dokploy:
   - ב-`kidsquiz-api`, Environment: `TURNSTILE_SECRET=<Secret Key>`
   - ב-`kidsquiz-web`, **Build Arg**: `VITE_TURNSTILE_SITE_KEY=<Site Key>`
   - Deploy לשניהם.
**אימות:** בטופס ההרשמה מופיע רכיב האימות; הרשמה בלעדיו נדחית; הרשמה רגילה עוברת. כל עוד המשתנים לא מוגדרים, ההרשמה ממשיכה לעבוד בלי Turnstile.

### 6. גיבוי: לבדוק שחזור של גיבוי עם נתונים
**למה:** שחזור נבדק רק על גיבוי ריק. הגיבוי של 85.2KB הוא הראשון שמכיל נתונים.
**מה לעשות:** ב-Dokploy → `kidsquiz-db` → Backups → Restore אל בסיס נתונים **זמני ונפרד** (לא על `kidsquiz`!). ואז להתחבר אליו ולהריץ: `SELECT count(*) FROM questions;` (צפוי: 1,525 ומעלה) ו-`SELECT count(*) FROM users;`. אחר כך למחוק את הבסיס הזמני.
**אימות:** הספירות תואמות את בסיס הנתונים החי. לתעד תאריך בדיקה.
**אחרי ההשקה:** לחזור על הבדיקה פעם בחודש.

### 7. ניטור: בדיקת התראה בפועל
**מה לעשות:** להשבית זמנית את `kidsquiz-api` ב-Dokploy (Stop) למשך כ-10 דקות, ולוודא שהגיעה התראת UptimeRobot (מייל/טלגרם). להפעיל מחדש ולוודא שחזרה התראת "חזר לפעול".
**אימות:** שתי ההתראות התקבלו. אם לא: לתקן את ערוץ ההתראות (Alert Contacts).

### 8. חשבונות מנהל
**8א. לתקן/להסיר את החשבון שנוצר עם המייל `email`** (בצע רק אחרי שאישרת שיש מנהל תקין אחר שנכנס בהצלחה):
1. ב-Dokploy → `kidsquiz-db` → Terminal, להתחבר ל-`psql` ולבדוק:
   ```sql
   SELECT id, email, role, disabled, last_login_at FROM users WHERE role = 'admin';
   ```
2. לנטרל (לא למחוק עדיין):
   ```sql
   UPDATE users SET disabled = true WHERE email = 'email' AND role = 'admin';
   DELETE FROM sessions WHERE user_id IN (SELECT id FROM users WHERE email = 'email');
   ```
3. אחרי שבוע, אם הכול תקין, מוחקים: `DELETE FROM users WHERE email = 'email' AND role = 'admin';` (היומן נשמר, והפעולות שלו יוצגו בלי שם).
**8ב. מנהל שני:** בטרמינל של `kidsquiz-api` (תיקייה `/app/server`):
`npm run seed:admins -- --email <מייל-אמיתי> --first <שם> --last <משפחה>`
הסיסמה נשאלת בטרמינל (לפחות 10 תווים, ייחודית, ממנהל סיסמאות).
**אימות:** שני המנהלים נכנסים; חשבון `email` חסום או לא קיים.

### 9. GitHub ו-Auto Deploy
- **הגנת ענף `main`:** Settings → Branches → Add rule: חובה Pull Request או לפחות איסור force-push ומחיקה של `main`.
- **Auto Deploy:** לוודא ב-Dokploy ששני השירותים (`web`, `api`) מוגדרים לפרוס אוטומטית מ-`main` (Webhook), ולבדוק על שינוי קטן.
- **אבטחה:** לוודא שאין בהיסטוריית Git סודות (`git log -p | grep -i password` או כלי כמו gitleaks). לא נמצאו קבצי `.env` במאגר.
- Secret Scanning של GitHub (חינמי): Settings → Code security.

### 10. דפי משפט ופרטיות (באחריות הלקוחה, עם עזרה שלך)
המערכת שומרת מידע אישי של **ילדים** (שם, עיר, טלפון, מייל, תאריך לידה). הלקוחה (בעלת התוכן) צריכה להחליט מול גורם משפטי על:
- מדיניות פרטיות: איזה מידע נאסף, למה, כמה זמן נשמר, למי מועבר (Cloudflare, Contabo), זכות עיון ומחיקה, מי איש הקשר.
- תנאי שימוש (כולל תקופת ניסיון ומנוי).
- הצהרת נגישות (עם פרטי רכז נגישות).
- הסכמת הורים להרשמת קטינים, וחובת רישום מאגר מידע / דיווח לפי חוק הגנת הפרטיות (תיקון 13), אם רלוונטי.
אני מכין שלד טכני (דפים וקישורים בטופס ההרשמה, ותיבת סימון הסכמה) ואת הטקסטים צריך לקבל מהלקוחה. נא להעביר לי את הטקסטים הסופיים כשיהיו.

## 11. מה אני מבצע (ואיך זה משפיע על ההגדרות שלך)
**עודכן: כל סעיפי הקוד שלהלן בוצעו ונבדקו (36 בדיקות שרת, בנייה, בדיקת CSP בדפדפן).** סדר הפריסה ותוספות למסך הניהול: `docs/DOKPLOY_API_SETUP.md` סעיף 11. הפריסה ל-Dokploy תתבצע אחרי שתאשר לדחוף.

אני מבצע בקוד, עם בדיקות לכל סעיף:
- תיקון נעילת חשבון דרך שם משתמש, הגבלת קצב נכונה (IP אמיתי מ-Cloudflare, לפי חשבון ובכיתה משותפת), ונעילה זמנית אחרי ניסיונות כושלים.
- אכיפת תוקף מנוי גם על התחברות קיימת.
- מסך ניהול: הארכה/שינוי סטטוס מנוי, חסימה ושחרור, מחיקת תלמיד ויצוא נתוני תלמיד, צפייה ביומן פעולות ושחזור שאלה שנמחקה.
- הגבלת גודל ותקינות לתוצאות והתקדמות; `pool.on('error')`; בדיקת מייל בסקריפט יצירת מנהל.
- כותרות אבטחה והידוק CSP באתר, `no-store` ל-API.
- Turnstile (אופציונלי, נדלק לפי משתני הסביבה שבסעיף 5).
- שלד דפי פרטיות, תנאים ונגישות.

**מה תצטרך לעשות אחרי שאסיים:** ב-Dokploy לפרוס מחדש את `kidsquiz-api` ואת `kidsquiz-web` (אחרי ה-push), ולהוסיף את משתני Turnstile (סעיף 5) כשתהיה מוכן. אין שינוי סכמה שדורש פעולה ידנית. אם יתווסף שינוי כזה, אודיע בנפרד, והמיגרציה רצה אוטומטית בעליית השרת.
