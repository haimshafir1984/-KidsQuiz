# הקמת שירות ה-API ב-Dokploy

המדריך מניח שכבר קיימים: הפרויקט KidsQuiz ב-Dokploy, שירות האתר (Dockerfile בשורש) ובסיס הנתונים `kidsquiz-db` (PostgreSQL 16, גיבוי יומי ל-R2, פנימי בלבד).

**סדר הפעולות חשוב:** קודם מקימים את ה-API ומוודאים שהוא עובד, ורק אחר כך מדליקים את האתר במצב שרת (שלב 6). עד אז האתר ממשיך לעבוד כדמו.

---

## 1. מה צריך מוכן
- הקוד ב-GitHub על `main` (הקומיט שמכיל את התיקייה `server/`).
- פרטי בסיס הנתונים (ממסמך הסיום שלך): משתמש `kidsquiz_app`, בסיס `kidsquiz`, כתובת פנימית `kidsquiz-kidsquizdb-29pqtk`, פורט `5432`. הסיסמה נמצאת ב-Dokploy בשירות בסיס הנתונים.

## 2. יצירת האפליקציה
בפרויקט KidsQuiz: **Create Service → Application**.

| שדה | ערך |
|---|---|
| Name | `kidsquiz-api` |
| Source | Github, אותו מאגר, Branch `main` |
| Build Type | **Dockerfile** |
| Docker File | `server/Dockerfile` |
| Docker Context Path | `.` (נקודה, שורש המאגר. **חשוב**: הסקריפט שמייבא שאלות קורא את `src/data`) |
| Docker Build Stage | ריק |

## 3. משתני סביבה (Environment)
לשמור בלשונית **Environment** של `kidsquiz-api`:

```
NODE_ENV=production
PORT=3000
DATABASE_URL=postgres://kidsquiz_app:<הסיסמה>@kidsquiz-kidsquizdb-29pqtk:5432/kidsquiz
PUBLIC_URL=https://kidsquiz.flowsbiz.com
```

אופציונליים (יש ברירת מחדל):
```
SESSION_DAYS=30         # כמה ימים תלמיד נשאר מחובר
ADMIN_SESSION_DAYS=7    # כמה ימים מנהל נשאר מחובר
TRIAL_DAYS=180          # תקופת ניסיון בהרשמה. יוחלף בסטטוס מנוי כשיחובר תשלום
TRUST_CLOUDFLARE_ONLY=true  # להפעיל רק אחרי אימות (ר' USER_ACTIONS_REMAINING.md): מאמין לכתובת הלקוח רק כשהחיבור מ-Cloudflare
TURNSTILE_SECRET=...    # רק אחרי יצירת ווידג'ט Turnstile (ר' למטה). ריק = הרשמה בלי Turnstile
```

הערות:
- אם בסיסמה יש תווים מיוחדים (`@ : / # ?`) צריך לקודד אותם בכתובת (למשל `@` ל-`%40`). הכי פשוט להשתמש בסיסמה אלפא-נומרית.
- `PUBLIC_URL` חייב להיות הכתובת המדויקת של האתר ב-https. השרת חוסם בקשות שמשנות נתונים ממקור אחר.
- אין צורך ב-`SESSION_SECRET` או בהגדרות מייל: ההתחברות עובדת עם אסימונים אקראיים שנשמרים (כ-hash) בבסיס הנתונים. מייל יתווסף כשייבחר ספק.
- הסיסמה לא נכנסת ל-Git. היא רק ב-Dokploy.

## 4. נתיב (Domains)
בלשונית **Domains** של `kidsquiz-api`, להוסיף:

| שדה | ערך |
|---|---|
| Host | `kidsquiz.flowsbiz.com` (אותו דומיין של האתר) |
| Path | `/api` |
| **Strip Path** | **כבוי** (השרת מצפה לקבל את `/api/...` כמו שהוא) |
| Container Port | `3000` |
| HTTPS | מופעל. Certificate: כמו באתר (Let's Encrypt, מאחורי Cloudflare) |

בשירות **האתר** אין צורך לשנות דבר: Traefik נותן עדיפות לנתיב הספציפי יותר (`/api`) על פני `/`.

## 5. פריסה ובדיקה ראשונה
1. **Deploy** על `kidsquiz-api`. בלשונית Logs צריך לראות הודעות מיגרציה (טבלאות נוצרות) ואז שהשרת מאזין.
2. בדיקה מהדפדפן: `https://kidsquiz.flowsbiz.com/api/health` צריך להחזיר `{"ok":true}`.
   - 404 מהאתר = הנתיב/Strip Path לא נכון.
   - 502/503 = השרת לא עלה. לבדוק Logs (בדרך כלל `DATABASE_URL`).

## 6. פקודות חד-פעמיות (בטרמינל של `kidsquiz-api`)
ב-Dokploy: `kidsquiz-api` → **Advanced / Terminal** (או Docker exec לקונטיינר). להריץ בתיקייה `/app/server`:

**א. יצירת שני חשבונות המנהלים** (פעם לכל מנהל; הסיסמה נשאלת בטרמינל ולא מוצגת, לפחות 10 תווים):
```
npm run seed:admins -- --email <מייל-המנהל> --first <שם> --last <משפחה>
```
לשכחת סיסמה של מנהל: אותה פקודה עם `--reset`.

**ב. טעינת השאלות הראשונית** (בטוח להרצה חוזרת. לא דורס שאלות שנערכו בניהול):
```
npm run import:questions
```
הפלט: `שאלות בקוד: N. נוספו: N`.

## 7. הדלקת האתר במצב שרת
בשירות **האתר** (לא ה-API):
1. לשונית **Environment**, להוסיף גם כ-**Build Arg**: `VITE_USE_API=true`
   (כמו `VITE_OFFLINE_DOWNLOAD_URL`, המשתנה נאפה בזמן בנייה ולכן חייב להיות Build Arg).
2. **Deploy** מחדש לאתר.
3. בדיקה: הרשמה כתלמיד חדש, כניסה, חידון; ואז כניסה עם חשבון המנהל, ובדיקה שמסך הניהול מציג את התלמיד.

**חזרה אחורה:** למחוק את `VITE_USE_API` מהאתר ולפרוס שוב. האתר חוזר לדמו המקומי (נתוני הדמו נשארים בדפדפנים).

## 8. מה משתנה למשתמשים אחרי ההדלקה
- חשבונות הדמו ב-localStorage לא עוברים לשרת: כולם נרשמים מחדש.
- מסך הניהול נראה ונפתח רק לחשבון עם תפקיד מנהל (ובנוסף השרת בודק הרשאה בכל פעולה, כך שגם גלישה ישירה ל-`/admin` או פנייה ל-API לא עוזרות לתלמיד).
- שחזור סיסמה במייל עדיין לא קיים (אין ספק מייל). התלמיד פונה למנהל, והמנהל מאפס לו סיסמה במסך הניהול: משתמשים → לחיצה על השורה → "איפוס סיסמה". האיפוס מנתק את התלמיד מכל המכשירים.
- התקדמות בחידון נשמרת בשרת, כך שאפשר להמשיך ממכשיר אחר.
- נושאים ריקים שהמנהל מוסיף (בלי שאלות) נשמרים רק בדפדפן שלו עד שיוזנו בהם שאלות. נושא עם שאלות נשמר בשרת.

## 9. תקלות נפוצות
| סימפטום | סיבה | פתרון |
|---|---|---|
| `/api/health` מחזיר 404 | Path/Strip Path | Path=`/api`, Strip Path כבוי |
| `/api/health` מחזיר 502 | השרת לא עלה | Logs של `kidsquiz-api`; לבדוק `DATABASE_URL` |
| `ECONNREFUSED` / `ENOTFOUND` בלוג | שם המארח הפנימי שגוי | להעתיק את ה-Internal Host מהגדרות בסיס הנתונים |
| `password authentication failed` | סיסמה שגויה/תווים מיוחדים | לבדוק את הסיסמה, לקודד תווים מיוחדים |
| בהרשמה "בקשה לא תקינה" (403) | `PUBLIC_URL` לא תואם לכתובת האתר | לתקן ל-`https://kidsquiz.flowsbiz.com` ולפרוס |
| ההתחברות לא נשמרת | עוגיה לא נשמרת | לוודא שהאתר וה-API על אותו דומיין ב-https |
| "יותר מדי ניסיונות כושלים" | נעילה זמנית אחרי 8 ניסיונות כניסה שגויים לאותו חשבון מאותה כתובת (או 50 מכל הכתובות), למשך 15 דקות | להמתין, או שמנהל מאפס סיסמה |

## 10. אחרי העלייה
- לוודא בלשונית **Backups** של בסיס הנתונים שהגיבוי היומי רץ גם עכשיו, כשיש בו נתונים אמיתיים.
- להוסיף ניטור ל-`https://kidsquiz.flowsbiz.com/api/health` (Uptime Kuma או שירות חיצוני).

## 11. עדכון גרסה: סדר פריסה (אבטחה, ניהול מנויים, פרטיות)

הגרסה הזו מוסיפה מיגרציה `002_consent.sql` (עמודות הסכמה לתנאים). היא רצה לבד בעליית ה-API ואינה מוחקת נתונים.

**סדר הפריסה:** 1) `kidsquiz-api`, 2) לוודא ש-`/api/health` תקין, 3) `kidsquiz-web`.
(אם האתר ייפרס לפני ה-API, ההרשמה תיכשל עד שה-API יתעדכן, כי השרת החדש דורש אישור תנאים.)

**אופציונלי: Cloudflare Turnstile להרשמה.** אחרי יצירת ווידג'ט:
- `kidsquiz-api`, Environment: `TURNSTILE_SECRET=<Secret Key>`
- `kidsquiz-web`, **Build Arg**: `VITE_TURNSTILE_SITE_KEY=<Site Key>` ופריסה מחדש לאתר.
כשהמשתנים לא מוגדרים ההרשמה ממשיכה לעבוד בלי Turnstile.

**מה חדש לבדיקה אחרי הפריסה:**
- בהרשמה יש תיבת אישור תנאים (חובה), ודפי `/terms`, `/privacy`, `/accessibility` (מסומנים "טיוטה" עד לאישור הטקסטים, ר' `LEGAL_DRAFT` ב-`src/pages/LegalPages.jsx`).
- במסך הניהול: ב"משתמשים" (לחיצה על תלמיד) יש הארכת מנוי, סיום מנוי, חסימה/שחרור, איפוס סיסמה, הורדת נתוני תלמיד ומחיקה. בלשונית "שחזור ויומן": שחזור שאלות שנמחקו ויומן פעולות.
- באזור האישי של תלמיד: "הנתונים שלי" (הורדה ומחיקת חשבון).
- ה-API מזהה כתובת לקוח לפי `CF-Connecting-IP` של Cloudflare. גישה ישירה לשרת (עוקפת Cloudflare) יכולה לזייף כתובת, ולכן כדאי להגביל את הגישה לשרת מהאינטרנט לפורטים 80/443 דרך Cloudflare בלבד (ר' USER_TASKS_BEFORE_LAUNCH).
